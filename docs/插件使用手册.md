# DSH 插件使用手册（详细版）

> 面向 DSH 使用者：**怎么安装、怎么使用、怎么验证** 这两个插件，全部基于真实跑通的流程。
> 插件开发/发布流程见 [发布流程.md](./发布流程.md)。

## 插件一览

| 插件 | 工具 | 功能 | 状态 |
|------|------|------|:---:|
| `@cqpdrcuk/dsh-plugin-npm-advisor` | `npm_package_audit` / `npm_dependency_tree` | 装新 npm 包前，判断这个包是不是最优解（原生替代/维护健康度/依赖树） | ✅ 已上线 npm 0.1.x + 1024Store |
| `@cqpdrcuk/dsh-plugin-hardware-benchmark` | `hardware_benchmark` | 读本机硬件，开发/游戏双维打分 + 网络实测 + DIY 升级建议 | ✅ 已上线 npm 0.1.x + 1024Store |

# 一、安装

## 1.1 前置

- DSH 已安装（`dsh` CLI，或桌面壳 `deepseek-harness-desktop`）
- 版本建议 `0.1.0-rc.6+`（插件依赖 cordis/dsh-tools 已发布版本）

## 1.2 标准安装（有 dsh CLI）

```sh
# npm 包方式（推荐）
dsh plugin --profile web add @cqpdrcuk/dsh-plugin-npm-advisor
dsh plugin --profile web add @cqpdrcuk/dsh-plugin-hardware-benchmark

# 或 GitHub 源码方式（1024Store 收录的安装规格）
dsh plugin --profile web add github:ERVeepp/dsh-plugins#path:packages/tool-npm-advisor
dsh plugin --profile web add github:ERVeepp/dsh-plugins#path:packages/tool-hardware-benchmark
```

装完**重启 DSH**（或重开桌面壳），插件随 bundle 激活。

> ⚠️ **版本坑**：0.1.0 曾把入口指向 TS 源码（`src/index.ts`），DSH 从 node_modules 加载时会报
> `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` 导致整个 profile 崩。**0.1.1 起改为发布编译产物（`dist/index.mjs`）**，正常使用。

## 1.3 桌面壳环境安装（deepseek-harness-desktop）

壳内 `dsh` 不在 PATH，用完整路径 + DSH_HOME：

```powershell
# 定位壳内 DSH（版本号按实际）
$env:DSH_HOME = "$env:APPDATA\deepseek-harness-desktop\dsh-home"
$dsh = "$env:APPDATA\deepseek-harness-desktop\versions\0.1.0-rc.7\node_modules\.bin\dsh.CMD"

# 安装
& $dsh plugin --profile web add @cqpdrcuk/dsh-plugin-npm-advisor
& $dsh plugin --profile web add @cqpdrcuk/dsh-plugin-hardware-benchmark

# 启动 Web UI（浏览器访问 http://127.0.0.1:3080）
& $dsh web --no-open
```

## 1.4 验证安装成功（三查）

**① 包已进 profile 依赖树**：看 `dsh-home/profiles/web/package.json` 的 `dsh.profile.bundles`：

```powershell
$h = "$env:APPDATA\deepseek-harness-desktop\dsh-home"
Get-Content "$h\profiles\web\package.json" | ConvertFrom-Json | % { $_.dsh.profile.bundles }
# 应包含：@deepseek-ai/dsh-base, @deepseek-ai/dsh-web-app,
#          @cqpdrcuk/dsh-plugin-npm-advisor, @cqpdrcuk/dsh-plugin-hardware-benchmark
```

**② 包目录里有 dist 产物**（0.1.1 正确形态）：

```powershell
Get-ChildItem "$h\profiles\web\node_modules\@cqpdrcuk\dsh-plugin-npm-advisor\dist"
# 应有 index.mjs / index.d.mts
```

**③ 入口指向 dist**（不是 src/index.ts）：

```powershell
(Get-Content "$h\profiles\web\node_modules\@cqpdrcuk\dsh-plugin-npm-advisor\package.json" -Raw) -match '"main": "dist/index.mjs"'
# True
```

## 1.5 卸载

```sh
dsh plugin --profile web remove @cqpdrcuk/dsh-plugin-npm-advisor
```

# 二、使用

## 2.1 前置：配模型

DSH 是 Agent Harness，agent 调工具前必须先配好 LLM 模型：

1. 打开 Web UI（`http://127.0.0.1:3080`）
2. **设置 → 模型 / Provider**，添加模型（DeepSeek / OpenAI 兼容均可），填 API Key + 模型名
3. 保存后新建对话，agent 才能调用插件工具

## 2.2 打开 Web UI

```sh
dsh web                 # 起服务并自动开浏览器
# 或壳内： & $dsh web --no-open，手动开 http://127.0.0.1:3080
```

## 2.3 插件 1：npm-advisor（装包前审查）

### 工具与参数

| 工具 | 参数 | 返回 |
|------|------|------|
| `npm_package_audit` | `packageName`（必填） | JSON：registry 元数据 + 原生替代/弃坑命中 + README 头部迁移声明 |
| `npm_dependency_tree` | `packageName`；`depth`（默认 2） | mermaid 依赖图 |

### 对话示例（直接说）

| 你说 | Agent 调 | 预期 |
|------|------|------|
| "我想装 axios，合适吗？" | `npm_package_audit("axios")` | `nativeAlternative: "原生 fetch（Node 18+）"` |
| "moment 还能用吗？" | `npm_package_audit("moment")` | `deadPackage: "维护模式，推荐 dayjs/date-fns"` + README 迁移线索 |
| "axios 会带多少依赖？" | `npm_dependency_tree("axios", 2)` | mermaid 依赖图 |
| "lodash 值得装吗" | `npm_package_audit("lodash")` | 逐场景判断原生可替代性 |

### 输出字段解读

`npm_package_audit` 返回 JSON 关键字段：

| 字段 | 含义 |
|------|------|
| `deprecated` | 该包是否被废弃（官方标记） |
| `lastPublish` / `publishedCount` | 最后发布时间 / 发版次数（维护活跃度） |
| `maintainers` | 维护者 |
| `directDependencies` | 直接依赖数量（依赖膨胀） |
| `readmeHead` | README 头部 1500 字符（弃坑/迁移声明常写在这） |
| `nativeAlternative` | 命中原生替代映射表（如 axios → fetch） |
| `deadPackage` | 命中弃坑/维护停滞表（如 moment） |

> 原理：**插件给事实，模型裁决**。模型结合 `readmeHead` 的迁移声明 + 自身知识做最终选型。

## 2.4 插件 2：hardware-benchmark（硬件打分 + 升级）

### 工具与参数

| 工具 | 参数 | 返回 |
|------|------|------|
| `hardware_benchmark` | 无 | JSON：硬件画像 + dev/game/network 分 + 升级建议 |

### 对话示例

| 你说 | 得到 |
|------|------|
| "看下我这台电脑适不适合做开发和打游戏" | 开发/游戏双维分数 + 等级 + 网络实测 + 升级建议 |
| "帮我列个升级清单，带参考价" | `hardware_benchmark` 拿建议 → agent `web_search` 查价 → 带价格清单 |
| "这台机器跑 AI 本地推理行吗" | 从内存/CPU/GPU 维度给判断 |

### 输出解读

```json
{
  "hardware": { "cpuModel": "Ryzen 7 8700G", "totalMemGB": 31, "memType": "DDR5",
                "gpuModel": "NVIDIA GeForce RTX 5070 Ti", "gpuVramGB": 16,
                "gpuList": [{"model":"AMD Radeon 780M Graphics","vramGB":1}, {"model":"NVIDIA GeForce RTX 5070 Ti","vramGB":16}],
                "downloadMbps": 320 },
  "dev":     { "score": 84, "grade": "A", "reasons": ["..."] },
  "game":    { "score": 95, "grade": "S", "reasons": ["..."] },
  "network": { "score": 80, "grade": "A", "reasons": ["实测下载 320Mbps：主流水平"] },
  "overall": "全能工作站（开发 + 游戏通吃）",
  "upgrades": [ { "priority": "high", "costBand": "low", "part": "内存", "current": "31GB DDR5",
                  "suggestion": "...", "recommendation": "...", "searchHint": "DDR5 32GB 2x16GB 6000MHz 价格" } ]
}
```

关键点：

- **`hardware.gpuModel` 是独显优先选中的**（排除核显），`gpuList` 列出全部 GPU
- **评分维度**：开发 = CPU 多核(40) + 内存(30) + 磁盘(30)；游戏 = GPU(60) + CPU 单核(25) + 内存(15)；网络 = Cloudflare 实测（失败按网卡估算）
- **`upgrades`** 是 DIY 玩家口吻：DDR4→DDR5 兼容性、性价比排序（`costBand` low→high）、每条含 `recommendation`（推荐规格）+ `searchHint`（查价搜索词）
- **价格实时查**：模型按 `searchHint` 调 `web_search` 查当前价，插件不硬编码

## 2.5 常见问题

| 问题 | 说明 |
|------|------|
| 某指标显示 null | 该项采集失败（虚拟机/无独显/断网），插件容错降级，不影响整体 |
| 游戏分低且 gpuModel 是核显 | 检查 `gpuList`：若独显在列表里但没被选中 → 可能是老版本（0.1.0），升级到 0.1.1 |
| 价格查不到/过时 | 依赖模型 `web_search` 联网，没网就没有；价格本身动态，以实时查询为准 |
| agent 不自动调工具 | 先确认模型已配置（2.1）且工具已激活（1.4 三查） |

# 三、验证

## 3.1 本地验证（开发期，不依赖 DSH/模型）

在 `dsh-plugins` 仓库根：

```sh
pnpm typecheck            # 全仓库类型检查（两包）
pnpm smoke                # npm-advisor 逻辑冒烟（moment/axios/依赖树）
pnpm smoke:hardware       # 硬件评分冒烟（三档 mock 硬件 + 升级建议）
pnpm load-test            # Cordis 加载 + 工具注册（npm-advisor）
pnpm load-test:hardware   # Cordis 加载 + 工具注册（hardware）
```

真机采集验证（看 GPU 独显选取是否正确）：

```sh
pnpm --dir packages/tool-hardware-benchmark exec tsx scripts/check-gpu.ts
# 应看到 gpuModel 是独显（如 RTX 5070 Ti），gpuList 列出全部 GPU
```

dist 产物验证（模拟 DSH 从 node_modules 加载，确认无 TS stripping 错）：

```sh
node packages/tool-npm-advisor/scripts/load-test-dist.mjs
# [PASS] dist 产物加载 + 工具注册全部通过
```

## 3.2 DSH 运行时验证（端到端）

1. **启动**：`dsh web`（或壳内 `& $dsh web --no-open`）——应打印 `dsh web: http://127.0.0.1:3080`，**无报错**（若报 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` = 装了 0.1.0 TS 版，升级 0.1.1）
2. **浏览器访问** `http://127.0.0.1:3080` → HTTP 200
3. **配模型**（设置 → 模型，填 key）
4. **对话验证**（推荐测试集）：

| 测试 | 输入 | 预期通过 |
|------|------|---------|
| 插件1 | "我想装 axios，合适吗？" | 返回原生替代 fetch 提示 |
| 插件1 | "moment 还能用吗？" | 返回维护模式 + 推荐 dayjs |
| 插件1 | "axios 依赖多吗" | 输出 mermaid 依赖图 |
| 插件2 | "看下我电脑适不适合开发/打游戏" | 返回双维分数 + 硬件画像（**gpuModel 应为独显**） |
| 插件2 | "列个带价格的升级清单" | 升级建议 + 实时价格 |

## 3.3 回归清单（改代码后必跑）

```sh
pnpm typecheck && pnpm smoke && pnpm smoke:hardware && pnpm load-test && pnpm load-test:hardware
node packages/tool-npm-advisor/scripts/load-test-dist.mjs   # dist 加载
pnpm --dir packages/tool-hardware-benchmark exec tsx scripts/check-gpu.ts  # 真机 GPU
```

全绿 → 本地 OK → `pnpm -r build` 重建 dist → 发布 npm（照 [发布流程.md](./发布流程.md)）。
